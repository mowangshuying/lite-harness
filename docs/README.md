## 三、同步纪律

1. **冲突优先级：代码 > `AGENTS.md` > `architecture.md` > 其余。** 发现文档与代码矛盾，以代码为准
   并**当场修文档**——只写一句「以代码为准」了事，正是失真得以积累的原因。
2. **行号锚点会腐化。** 本目录大量结论标注 `文件:行号`。改动源文件后，凡被触及的锚点都要重测；
   `async-chain-design.md` 是反面样本：一次拆分（旧 `AgentLoop.cpp` 2063 行 → 13 个 TU）让全文锚点
   100% 失效，靠它自己的 §8 存档说明才没误导读者。
3. **版本号是示例，也要跟着同步。** README / AGENTS / architecture / regression-checklist 与若干源码
   注释把当前版本（`s12.6`）当示例写死；升版本时随 `git grep` 逐处改，做法见 `AGENTS.md`「发布」节
   第一条。
4. **零散笔记不在 `docs/` 落地。** 临时方案、验收记录、会话草稿一律写到
   `.lite-harness/sessions/<id>/.temp/`；收口时把仍然成立的内容折进上表某篇权威文档、过时者删除，
   不在 `docs/` 里留孤立 md——孤立文件既无人引用、也无人负责同步。
5. **新增文档请做两件事：** 用 ASCII 文件名（现存那篇中文名 + 含空格的文件无法被链接稳定引用），
   并在本索引登记一行，同时从 `AGENTS.md` 或 `README.md` 建一条入口链接。没有入口的文档等于不存在。
