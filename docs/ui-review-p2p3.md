## P2：UI 层契约测试（5 个套件，≥32 条断言）

背景：测试目标只链接 `Qt6::Core`（见 `CMakeLists.txt` 单测节），因此可测对象必须是
不依赖 `Qt6::Gui` 的纯逻辑。当前 UI 层有三处「跑得通但结果不对、没有失败信号」的契约
完全没测，而它们都是用户可手改或代码易漂移的面。

| 套件 | 被测 | 关键断言 | 为什么必须测 |
|---|---|---|---|
| `tst_tooltagkind` | `ToolTagKindNames::nameForTool` | 全部 16 个工具名的类别映射、未知名/空串回落 `other`、大小写敏感 | 映射错一个 → 时间线标签配色错，无报错；QSS 选择器按类别名匹配，拼错即静默无色 |
| `tst_toolnames` | `ToolNames` 常量表 | 全部非空、无重复值、每个常量都能被映射到非 `other` 类别 | 常量表与映射表分家是典型的「改一处漏一处」 |
| `tst_navkeys` | `NavKey` 常量 | `SessionPrefix` 是 `SessionKeyFmt` 前缀、`SessionKeyFmt` 含 `%1`、各键非空且唯一 | 键格式漂移 → 恢复会话与新建会话键撞车，表现为「打开旧会话变成新会话」 |
| `tst_layoutconst` | `LayoutConstants` 全常量 | 全部尺寸为正、命中区 ≥32、窗口最小宽 > 栏宽、栏宽上限关系 | 布局常量改错无编译错误，只在特定窗口尺寸下露馅 |
| `tst_agentconst` | `AgentConst` 数值域 | `min < default < max`（4 组）、键名非空且唯一 | 域写反 → 所有合法配置被判非法并静默回退默认，表现「设置页改了不生效」 |

## 明确不做的项（记录理由，避免下轮重复提议）

- **QSS 三主题去重**：三份 `stylesheet/<theme>/` 是 FluentUI 换肤契约的一部分，
  合并成「公共 + 覆盖」会让改一处颜色需要读两层规则，调试成本高于重复成本。
- **`tr()` 重复字符串合并**：同一文案在不同上下文里可能独立翻译（如「取消」在
  设置页与审批卡语气不同），合并会锁死这种自由度，收益仅字数。
- **设置页卡片类拆分**：单文件 1400 行确实偏长，但拆分类会新增 6 个文件与跨文件
  成员访问，收益是「读起来短一点」，不改变任何行为 —— 不满足「改动即收益」的门槛。
